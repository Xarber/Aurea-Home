# Native remote keyboard

Native Android/iPhone companions negotiate Android TV Remote Service IME alongside buttons and microphone. Field-status (`RemoteImeKeyInject`), batch-edit counters and show-keyboard events activate the TV keyboard panel. A new field opens it automatically on the native phone; acknowledgments for the same field do not repeatedly reopen it. A manual **TV keyboard** action remains in Settings when available. Browser/mobile web does not claim direct TLS field detection or automatically open a phone keyboard.

Text changes are sent immediately, without a Send button. `keyboardEdits.ts` computes a Unicode-aware common prefix, removes the old suffix with Android Delete key events, then inserts the replacement through standard IME batch-edit messages using current TV counters. This supports append, backspace, paste and edits within the phone's current text. Edits are serialized, never replayed after a failure, and cannot follow a TV switch, background transition or new field revision. Existing TV field contents/passwords are not read back; the phone editor represents only text entered during its current panel session. Some applications expose no compatible IME events.

Input is bounded to 1024 UTF-16 code units. Text is ephemeral: never saved, logged, synchronized, cached or added to Ideas. Closing the panel or changing TVs clears it. Desktop directional-key passthrough remains independent. Native text uses the already pinned mutual-TLS connection even if Home HTTP is unavailable; no shell encoding or ADB injection is used.

Protocol references: upstream [androidtvremote2 text handling](https://github.com/tronikos/androidtvremote2/blob/main/src/androidtvremote2/remote.py) and [IME schema](https://github.com/tronikos/androidtvremote2/blob/main/src/androidtvremote2/remotemessage.proto). Host tests exercise real TLS counters/payloads, field detection, edit deltas and TV-switch isolation. Physical iPhone/Android field detection, keyboard presentation and app-specific editing still require validation.
