# Native remote keyboard

Native Android/iPhone companions negotiate the Android TV Remote Service IME capability alongside existing buttons and microphone. A `RemoteImeShowRequest` opens a small TV keyboard panel; the TV's batch-edit messages supply current IME/field counters. **TV keyboard** is also available in the selected TV's system-controls settings when that native capability is ready.

The user types locally and explicitly sends a bounded string (up to 1024 UTF-16 code units). The native client sends the standard batch-edit message over the existing pinned mutual-TLS connection using the TV's current counters. No shell command injection or ADB text encoding is used. Typed text is not saved, logged, synchronized, cached or added to Ideas. Closing the panel or changing TV clears it. Existing desktop directional-key passthrough remains independent. The browser cannot connect directly to the native TLS/IME service, so it does not claim automatic field detection or native text entry; no mobile browser keyboard is opened automatically.

Some TV apps do not expose compatible IME messages. The manual panel remains a fallback on supported native services, and errors are visible. TV field contents/passwords are not read back. The implementation follows the upstream [androidtvremote2 protocol and text method](https://github.com/tronikos/androidtvremote2/blob/main/src/androidtvremote2/remote.py); the existing native wire test now exercises negotiated IME, field counters and a real TLS batch-edit payload. Physical app/keyboard compatibility still needs validation.
