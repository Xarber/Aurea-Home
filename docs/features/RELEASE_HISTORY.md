# What’s New, release history and developer notes

Aurea Home and Remote share `app/src/main/assets/release-history.json`, copied to the Expo assets by `scripts/release.py generate`. The archive covers all 28 existing version entries. Verified publication records link the six published application releases to exact tags, revisions, channels and dates. Entries without a verified public release are shown as reconstructed history or current development. The metadata-only source release has no product entry. Archived notes reflect the features and fixes documented for each version.

On phone, web and the primary Android TV interface, History shows up to three icon-led changes per version. Opening Full changelog shows every curated row and compatibility information for that version. On the website a URL such as `/?changelog=2.1.0` opens that version directly. Technical notes remain behind Developer Options. They are generated from the matching channel’s most recent recorded published ancestor, with a labeled reconstructed project baseline when none is available. Developer notes include exact commit IDs, bodies or up to six filenames. Public release notes contain curated user-facing rows and a full-notes link.

The optional first-launch tour acknowledges the current release when completed or skipped. Returning users see a version-matched announcement after the application is ready and relevant pairing or current modal work is clear. Android TV defers while music is active. Acknowledgment is written when the panel is dismissed. Same-version rebuilds use the same acknowledgment. Web uses local storage, mobile uses SecureStore, and Android TV uses application preferences with migration from recorded version codes. Aurea’s current builds have no OTA delivery identity.

Capture receipts record platform, device class, capture kind, viewport, version, source revision, date and digest. Earlier captures retained in the manifest were generated by real browser previews. Their historical receipt identified the source as local and did not provide an exact commit. A retained capture with missing source provenance cannot satisfy a required refresh. Genuine phone, tablet, and native TV screenshots, physical accessibility checks and release-time refresh evidence remain separate gates.
